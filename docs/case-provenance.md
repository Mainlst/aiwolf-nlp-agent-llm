# Qualitative case provenance

The recovered history contains a plan for the three qualitative case categories and a later note reporting their insertion. It does not recover a fully executable selection rule for the current case set. The historical excerpts below are preserved without rewriting their claims; the full internal notes and obsolete experiments are not included.

The [selection-plan excerpt](provenance/case-selection-plan-20260816.txt) is line 270 of `paper/acl-style-files-master/aiwolfdial2026_ja.tex` at commit `8245a921cf9ec64d9070f23a8f5968b53634f7eb` (August 16, 2026, 06:39:24 JST). It proposes one P+ PP success, one P−PP PP miss, and one P+ false-PP example. It specifies correspondence to quantitative metrics, complete required logs, and an observable mechanism, with a fixed-hash order for ties; it excludes game outcome and ease of presentation as selection criteria. It also specifies presenting public facts, the applicable instructions, raw output, validated output, and the actual vote, and using the cases illustratively rather than to estimate frequencies.

The [insertion-record excerpt](provenance/case-selection-record-20260816.txt) is the complete case-related sentence from line 240 of `doc/todo` at commit `82f1a0df90627512e600eb2aa6d24667149dbb1b` (August 16, 2026, 09:40:23 JST). It reports that PP-success, PP-miss, and false-PP cases were inserted using a fixed-hash order. Both records precede collection of the distributed reachable-board responses later that morning. The insertion note therefore documents an earlier case set; it does not by itself establish selection of every current replacement example.

Neither recovered excerpt defines the hash input, hash algorithm, seed, comparator, or complete candidate ordering. In particular, the selection procedure used for the current replacement false-PP case has not been established. The additional werewolf-view illustration is explicitly post hoc in the manuscript. This restoration does not construct a retrospective ordering or claim that the current four cases can be regenerated by the historical selection rule. Source commits, original file hashes, original line locations, extraction methods, and excerpt hashes are recorded in [case-selection.json](provenance/case-selection.json).
